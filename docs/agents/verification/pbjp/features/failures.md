# Fail safely without changing clipboard data

## User outcome

Successful requests exit 0; operational extraction failures exit 1; invalid CLI
usage exits 2. Pre-output failures use stderr and emit no stdout; an output write
failure can leave partial stdout. Every scalar or
boolean option is nonrepeatable, operands are rejected, information is
standalone, and incompatible modes are rejected. Success and failure leave the
selected pasteboard unchanged.

## How to reach it

Pass Doctor, authorize fixture writes, and seed only generated data with the real
`bin/pbjc`. Source entry points: `cmd/pbjp`, `internal/command.Command.Paste`,
Cobra validation in `internal/command`, and generation-aware snapshot access in
`internal/pasteboard/snapshot_darwin.go` and `pasteboard_darwin.m`.

## How to drive it

```sh
python3 scripts/verify-pbjp.py --allow-clipboard --feature all \
  --evidence ".scratch/pbjp-failures-$(date +%Y%m%d-%H%M%S)"
```

Use `--feature failures` for a focused sentinel-based usage and missing-format
pass. Full coverage also requires the `files` group's multi-item/index/newline
cases and the `representations` group's locale/empty/no-supported-format cases.

## Proof

The driver checks exit status, empty stdout, nonempty error diagnostics, and
unchanged generated bytes/metadata/change count for:

- Missing exact type and missing file URL format (exit 1).
- Empty type, missing flag argument, negative/nonnumeric item, unknown board or
  preference, unknown flag, bare `--null`, and operands including after `--`.
- Repeated type/item/pboard/prefer scalar flags, repeated files/null/list/help/
  version boolean flags, and repetition through short/native aliases.
- Type/files/prefer conflicts; list-types combined with type/files/prefer/null;
  mixed information options or information plus extraction/operands.
- Ambiguous default/exact multi-item reads and unavailable item indexes (exit 1,
  driven in `files`), with no accidental concatenation.
- Newline-unsafe file paths and unrepresentable locale output (exit 1 with no
  partial stdout), empty-board failures, and successful empty/default outputs.

A final successful default read still returns the exact generated sentinel.
Each drive records expected exit and stdout hashes only, not unexpected stderr
or clipboard bytes. Cleanup success is required before a VERIFIED verdict.

## Gotchas

The driver does not simulate clipboard races: generation checks in the observer
turn external mutation into a failed proof, not race coverage. Review native
change-detection tests for that property. Do not run alongside other pasteboard
writers. No test backs up old content, watches history, converts representations,
or shuts down unrelated processes. Boolean `=false` forms are rejected under the
CLI's true-only boolean option convention and are exercised by this group.
