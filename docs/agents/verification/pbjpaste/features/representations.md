# Extract representations and locale text

## User outcome

Default extraction emits plain UTF-8 text encoded in the selected locale, or raw
EPS then RTF when text is absent. `--prefer txt|rtf|ps` (also `ascii` for text and
native `-Prefer`) changes first choice but permits fallback. `-t/--type TYPE`
returns only the exact advertised representation, unchanged: no conversion,
conformance fallback, or added newline. Empty default/no-supported-format output
is successful; missing exact data is not.

## How to reach it

Build, pass Doctor, and authorize fixture writes. The driver starts with a fresh
generated `pbjcopy` fixture, never old clipboard contents.

Source entry points: `cmd/pbjpaste`; `internal/command.Command.Paste` for preference
and extraction; `internal/pasteboard/snapshot_darwin.go` (`Capture`, `Types`,
`Data`); `internal/pasteboard/text_darwin.go` (`EncodeText`); and
`internal/pasteboard/text_darwin.m` for native encoding resolution/conversion.
Fixture publication is the public `pbjcopy` path.

## How to drive it

```sh
python3 scripts/verify-pbjpaste.py --allow-clipboard --feature representations \
  --evidence ".scratch/pbjpaste-representations-$(date +%Y%m%d-%H%M%S)"
```

## Proof

- Custom binary data containing NUL, invalid UTF-8, CR/LF, and a trailing NUL is
  identical on exact extraction; an absent conforming type fails rather than
  converting. An unsupported default representation gives empty stdout, exit 0.
- HTML and separate plain fallback remain distinct and exact; default is plain.
- Rich-plus-plain fixtures distinguish RTF/PS preference from default text;
  native `-Prefer`, `txt`, and `ascii` work, and unavailable preferences fall
  back. An RTF-only fixture checks native derived-text availability: default uses
  readable advertised text, or skips an unavailable promised flavor and returns
  stored RTF. Exact unavailable text fails, and exact RTF preserves bytes.
  EPS-only output preserves bytes. A shared EPS/RTF-label fixture remains raw.
- `LC_ALL` overrides `LC_CTYPE` and `LANG`; unset/empty values fall through in
  that order, finally to C. Generated café becomes Latin-1 bytes where requested.
  Unrepresentable C-locale text fails without partial stdout. Exact UTF-8 bytes
  ignore the locale. ASCII succeeds with all locale variables absent.
- Empty plain text returns zero bytes in default and exact mode. A native clear
  of a previously generated fixture creates a genuine zero-item board: default
  returns empty success, listing returns `[]`, and exact/files/item requests fail.
- Native generated bytes, metadata, and change count remain unchanged around
  every `pbjpaste` read or failed request. Reports contain expected lengths/hashes,
  never unexpected data.

## Gotchas

Only the general clipboard is overwritten by this group, then reset to a harmless
completion message. The find/ruler/font boards remain **unexercised** and are
neither read nor written under general-only consent. `pbjcopy` assigns identical bytes to all
explicit raw type labels, so the shared EPS/RTF fixture cannot distinguish which
rich label won; it must not be cited as independent live proof of EPS-before-RTF
ranking with distinct payloads. The unavailable-derived-text case proves metadata
listing can succeed without fetching that unavailable payload. Generation-race
rejection has native tests; this serial driver does not inject a race. `pbjpaste`
itself performs no format conversion, OCR, clipboard history, or app rendering;
macOS or a publishing application may advertise generated representations.
